Multilingual — Examples

Each section shows what a single configuration option does, with input on the left and the wrapped output on the right.

How to use

Two patterns. Pick whichever fits.

// Pattern A — set defaults and auto-wrap on load
Multilingual.init({ autoInit: true, selector: '#content' });

// Pattern B — wrap on demand
Multilingual.wrap('#content', { /* per-call config */ });

1. Default behavior

No options — each writing system is detected and wrapped automatically. Whitespace and punctuation inherit the surrounding script.

Input
Hello 안녕하세요 こんにちは 你好 مرحبا
Output
Hello 안녕하세요 こんにちは 你好 مرحبا

2. glyphOverrides

Force specific characters to a script regardless of their Unicode block. Useful for brackets you want rendered in your Latin font even when surrounded by Korean, or for Arabic punctuation that should always group with Arabic.

no override — parens inherit Korean
인용문 (사람 이름) 끝.
{'()[]{}': 'latin'}
인용문 (사람 이름) 끝.

3. languageOverrides

Override the BCP-47 lang attribute emitted for a script. Browsers use lang for hyphenation rules, screen-reader pronunciation, and font fallbacks — so a Traditional-Chinese site usually wants zh-TW or zh-Hant, not the generic zh. Inspect the spans to see the attribute change.

default (lang="zh")
量子力学
{chinese: 'zh-TW'}
量子力学

4. useShortNames

When true (default), each span gets an ml-xx class for easy CSS targeting. When false, only lang and data-script are emitted — use this if you target solely via the data attribute. (The right column has no styling because the demo CSS only targets .ml-xx.)

useShortNames: true
Hello 안녕
useShortNames: false
Hello 안녕

5. skipElements

Tag names whose contents are skipped during traversal. Defaults to ['script','style','noscript','template']. Add 'code' to leave inline code blocks untouched.

default (code is wrapped)
Inline print('안녕') in prose.
skipElements: [..., 'code']
Inline print('안녕') in prose.
