Multilingual

한 단락 안에 섞인 여러 문자세트를 글자별로 골라내, 각 segment를 <span>으로 감싸 CSS로 따로 스타일링할 수 있게 해 주는 작은 라이브러리.

A tiny JavaScript library that splits mixed-script text into <span>s so each script can be styled independently in CSS.

왜 필요한가 · What & why

한글 본문 폰트로 영문이나 숫자를 표시하면 보통 못생긴 경우가 많아서, 영문에는 따로 영문 폰트(예: Inter, Helvetica)를 적용하고 싶어집니다. 그런데 한글 폰트와 영문 폰트는 폰트 메트릭(x-height, 베이스라인, advance width)이 달라서, 같은 font-size로 섞어 쓰면 시각적으로 균형이 깨지죠. 그래서 언어별로 font-size나 line-height, baseline을 미세 조정하고 싶지만, CSS의 font-family는 요소 단위로만 적용되니까 한 <p> 안에 섞인 한글과 영문을 따로 타깃팅할 방법이 없습니다.

Korean body fonts usually render Latin letters and digits poorly, so designers want a dedicated Latin font (e.g. Inter, Helvetica) for those parts. But Korean and Latin faces have different metrics (x-height, baseline, advance width), so mixing them at one font-size looks unbalanced — and CSS's font-family applies per element, so there's no way to target the Latin parts inside a paragraph that also contains Korean.

Multilingual은 텍스트를 문자 단위로 스크립트 감지해서, 연속된 같은 스크립트 글자들을 <span lang="…" data-script="…" class="ml-…">로 감싸 줍니다. 그러면 .ml-en과 .ml-ko에 각각 다른 font-family, font-size, letter-spacing 등을 줄 수 있어요. 아랍어처럼 RTL 스크립트는 direction: rtl까지 자동 적용 가능합니다.

Multilingual detects each character's script and wraps consecutive same-script runs in <span>s with lang, data-script, and ml-xx class. Now you can give .ml-en and .ml-ko different fonts, sizes, or letter-spacing. RTL scripts like Arabic can also receive direction: rtl at the segment level.

/* Korean body in Noto Sans KR; Latin parts in Inter, 95% size */
.ml-ko { font-family: 'Noto Sans KR', sans-serif; }
.ml-en { font-family: 'Inter', sans-serif; font-size: 0.95em; }
.ml-ar { font-family: 'Noto Naskh Arabic', serif; direction: rtl; }

설치와 초기화 · Install & init

단일 파일 multilingual.js 하나만 받아 <script>로 불러오면 됩니다. 의존성 없습니다. 모던 브라우저(Chrome 64+, Firefox 78+, Safari 11.1+)면 동작 — Unicode property escapes(\p{Script=...})에만 의존합니다.

A single multilingual.js file, no dependencies. Works in modern browsers (Chrome 64+, Firefox 78+, Safari 11.1+) — relies only on Unicode property escapes.

<script src="multilingual.js"></script>

그다음 세 가지 방식 중 하나로 호출합니다.

Then pick one of three usage patterns.

1) init() — 페이지 로드 시 자동 wrap

전역 설정을 한 번에 정해 두고, autoInit: true로 DOM 준비 후 자동 wrap을 예약하는 방식. 페이지 전체에서 같은 설정을 쓸 때 가장 간단합니다.

Set defaults once and let autoInit: true schedule a wrap after DOM ready — easiest when the whole page shares one configuration.

Multilingual.init({
  autoInit: true,
  selector: '#content',
  delay: 100,                         // ms to wait before wrap
  glyphOverrides: { '()[]{}': 'latin' },
});

2) Multilingual.wrap() — 일회성 호출

특정 시점에 특정 요소만 감싸고 싶을 때. 두 번째 인자로 그 호출에만 적용할 설정을 줄 수 있습니다.

For one-off use — wrap a single target now, with optional per-call config as the second argument.

Multilingual.wrap('#article', {
  separateNum: true,
  languageOverrides: { chinese: 'zh-TW' },
});

3) new Multilingual() — 재사용 인스턴스

같은 설정으로 여러 요소를 감쌀 때 인스턴스를 한 번 만들어 두면 깔끔합니다.

Build a reusable instance when applying the same config to many targets.

const ml = new Multilingual({ glyphOverrides: { '()[]{}': 'latin' } });
ml.wrap('#article');
ml.wrap('#sidebar');

참고: wrap()은 호출 시점에 DOM이 준비되어 있어야 합니다(요소가 존재해야 함). 페이지 로드와 동시에 자동으로 감싸려면 패턴 1을 쓰세요. 이미 감싸진 영역(data-script가 붙은 span 내부)은 자동으로 건너뛰므로 같은 요소에 wrap()을 여러 번 호출해도 안전합니다.

Note: wrap() needs the DOM ready (target must exist). Use pattern 1 for fire-and-forget on page load. Spans with data-script are skipped on re-traversal, so calling wrap() twice on the same element is safe.

옵션별 동작 · Configuration

각 옵션은 하나의 일만 합니다. 좌/우 비교로 차이를 확인하세요.

Each option does one thing. The before/after columns show what changes.

separateSpace / separatePunct / separateNum

기본 동작은 공백·문장부호·숫자가 주변 스크립트에 흡수되는 것입니다. 이 셋 중 하나를 true로 켜면 해당 카테고리가 독립 segment가 되고, 각각 ml-space / ml-punct / ml-num 클래스를 받습니다. 숫자에 tabular-nums를 적용하거나, 문장부호만 다른 폰트로 바꾸거나, 공백을 시각화하고 싶을 때 씁니다.

By default, spaces / punctuation / digits merge into the surrounding script's span. Turn any flag on to split that category into its own span (with ml-space / ml-punct / ml-num). Useful for tabular numerals, styled punctuation, or visible spaces.

분리된 카테고리는 inheritance 전파에 참여하지 않습니다. 예: "한국어, 좋아요"에서 separatePunct: true만 켜면 쉼표 다음의 공백은 ml-punct가 아니라 가장 가까운 진짜 스크립트(korean)에 붙어요.

Separated categories don't propagate during inheritance, so a stray space next to a separated comma still inherits the nearest real script — not the punct script.

특정 글자를 강제로 어떤 스크립트로 분류할지 지정합니다. 한글 본문 사이의 괄호를 항상 영문 폰트로 보이게 하거나, 아랍 문장부호(،, ؟)를 항상 아랍어 segment에 묶고 싶을 때 유용합니다.

Force specific characters to a script regardless of Unicode block. Useful for brackets that should render in your Latin font even inside Korean, or Arabic punctuation that should group with Arabic.

languageOverrides

스크립트별 lang 속성값을 바꿉니다. 브라우저는 lang을 하이프네이션, 스크린리더 발음, 폰트 폴백에 사용하므로, 번체 중국어 사이트는 zh-TW나 zh-Hant가 필요합니다 (기본 zh로는 부족). 아래 두 segment 옆 작은 라벨이 실제 lang값입니다.

Override the BCP-47 lang value emitted for a script. Browsers use lang for hyphenation, screen-reader pronunciation, and font fallback — so a Traditional-Chinese site usually wants zh-TW or zh-Hant, not generic zh. The small labels next to each span below show the actual lang.

기본값 true면 각 segment에 ml-xx 클래스를 답니다. false면 lang과 data-script만 출력됩니다 — CSS를 attribute selector로만 타깃팅한다면 클래스를 생략할 수 있어요. (아래 오른쪽 칸은 데모 CSS가 .ml-xx만 타깃해서 스타일이 안 보이는 게 정상입니다.)

종합 예시 · Complex sample

다섯 언어의 양자역학 본문에 옵션을 여러 개 쌓아 적용한 예. 본문 안 괄호를 라틴으로 강제, 중국어 lang을 zh-CN으로 지정, 숫자를 분리, 인라인 <code>는 건드리지 않게 설정했습니다.

  languageOverrides: { chinese: 'zh-CN' },

역사 · History

이 라이브러리는 2016년 공개된 multilingualjs/multilingual.js의 컨셉을 이어받은 v2입니다. 원본은 어도비 인디자인의 합성글꼴(Composite Fonts) 기능에서 영감을 받아, 한 단락 안에 섞인 여러 문자세트를 글자별로 골라내 따로 스타일링할 수 있게 한 jQuery 플러그인이었습니다. ml-en, ml-ko, ml-num, ml-punct 같은 클래스 이름 규약은 원본에서 그대로 가져왔습니다.

This is a v2 carrying forward the concept of multilingualjs/multilingual.js (2016) — a jQuery plugin inspired by Adobe InDesign's Composite Fonts feature. The class-name convention (ml-en, ml-ko, ml-num, ml-punct) is inherited from the original.

v2는 같은 컨셉을 유지하면서 현대화했습니다: 의존성 제거, Unicode property escapes 기반 감지, 지원 문자세트 확대(10개 + 카테고리 3개), 단순화된 API, ~270줄. 자세한 변경 이력은 HISTORY.md를 참고하세요.

v2 is a modernization: zero dependencies, Unicode property escape detection, ten supported scripts plus three categories, a simpler API, and ~270 lines total. See HISTORY.md for the change log.
